# Step 5 management workspace

Select an ACTIVE society as its Committee Admin. Buildings, Flats, Residents and CSV imports appear in the sidebar. Platform scope and ordinary resident roles cannot open these screens. Backend authorization independently enforces every operation; frontend role/permission guards are UX.

Directories support active/archived/all filters, bounded search, allowlisted sorting/order and 20-row pagination. The flat directory also offers a paginated building filter. Create/edit forms use existing accessible controls/dialogs and display safe server validation/conflict errors. Flat building and occupancy resident selectors paginate/search server data rather than silently truncating the directory. Resident creation does not create an account; permanent optional references are generated when blank. Duplicate names/mobile remain distinct.

Flat details display current occupants, historical occupancies and all scheduled/current/history records on separately paginated lists. All four occupancy types are available, including simultaneous owner/tenant. Start/end are inclusive calendar dates; the API uses society-local today. End occupancy preserves its original start/person/type and closed history is read-only. Archives preserve all history and reserve identifiers; ongoing occupancy and child dependencies must be ended/archived first.

CSV imports use exact downloadable blank templates. Upload UTF-8 .csv (256 KiB / 500 rows), validate, inspect paginated row errors/warnings, correct in the tab or reupload, preview again, acknowledge warnings, then confirm through an explicit dialog. CSV edits disable confirmation until a new preview. Revalidate if society data changed. People are reused only by explicit society resident reference; matching name/mobile never auto-merges. Larger datasets require separate reviewed batches. XLSX is deferred because no archive/spreadsheet library was selected; the text-only path avoids macros/ZIP expansion and supports the full requested review flow.

The tab keeps CSV in component memory only. Review is staged privately on the server for 24 hours, limited to its creating administrator. Confirmation/cancellation clears staged personal values; expired reviews are blocked and maintenance clears their payload. Starting another import clears the editor and leaves the earlier staged review in history until cancelled/expired. Reload can inspect a staged preview but requires a corrected CSV reupload to change it. Completed result counts and evidence remain visible.

New lazy shells: /society/buildings, /society/flats, /society/persons, /society/flats/:id, /society/imports. The service worker caches static shell files only; dataGroups and URL asset patterns remain empty. Every API request has cache=no-store. No private CSV/profile/occupancy/preview data enters storage or worker caches. There are no financial screens or APIs in this step.

Run npm run check, npm run test:e2e and npm audit.
