# Maintenance and billing

Routes: `/society/billing/configuration`, `/society/billing/periods`, `/society/billing/generate`, `/society/billing/bills`, `/society/billing/bills/:id` and `/society/billing/outstanding`. Finance navigation/guards use the active society's read permission. Separate configuration/generation/discount actions use their dedicated capabilities. These are UX only; the API independently rechecks every session, membership, permission and identifier. Platform status does not show tenant finance navigation.

Create immutable charge types/versions and calendar-month or one-day event periods. Paginated billing lookups work for Accountants without exposing resident identities. Select at most 50 flats across pages, add only permitted discounts with a reason, request the exact server preview, review item rates/quantities, exclusions and totals, then explicitly confirm issue. No authoritative money is calculated in the browser: decimal strings are displayed exactly. Approved monthly policy is full amount on the month's first day with no proration. Flat rules override building rules, then society defaults. Issued gross/item snapshots remain unchanged; discounts appear as credits and prior outstanding is informational rather than new debt.

An in-memory UUID idempotency key is retained for retry after an uncertain network response. Editing the selection or discounts invalidates the preview/key and requires fresh review. Never persist keys, requests, bills or private responses in browser storage. Unknown safe API errors do not render arbitrary server details. Lists and lookups paginate; field/server errors remain accessible through shared controls. Existing PWA static-only policy remains: route navigation caches the shell code only; all `/api/**` responses bypass worker caching and use no-store. Offline financial screens display a connection error.

Run `npm run check` and `npm run test:e2e`. Managed Windows local startup lives in the backend (`npm run local:stop`, `npm run local:start`) and rebuilds the PWA/API at `http://127.0.0.1:4200`. Use existing isolated credentials, select an ACTIVE society and test configuration → periods → preview → issue → details/report. Also verify Accountant action restrictions, resident guards, invalid-form feedback, keyboard/mobile behavior, duplicate issue safety and no financial cache entries.
