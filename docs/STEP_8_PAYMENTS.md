# Payment recording UX

Finance routes: `/society/billing/payments` (history), `/new` (record), `/report` (collections), `/:id` (details), `/:id/receipt` (printable receipt) and `/:id/correct` (replacement). The existing Maintenance navigation contains Payments and Collection report. Guards use active society finance.read; record actions require finance.record, while refund/reversal/correction actions require finance.reverse. Backend session/membership/permission and tenant validation remains authoritative. Platform status confers no access.

Select a flat, tenant person payer (no login required), authorized collector and local payment date. Enter CASH/UPI/BANK_TRANSFER/CHEQUE, decimal-string amount, optional notes and required noncash reference. Allocate across paginated issued bills for that flat, using full or partial amounts. Exact BigInt UI totals help review; the server revalidates all balances. Confirm physical receipt explicitly before recording. Excess/unapplied money is rejected. Recorder and society are derived by the API, never posted.

History includes effective amount and RECORDED/PARTIALLY_REFUNDED/REFUNDED/REVERSED status. Details include immutable receipt labels and original allocations. The native Print receipt action hides application chrome and includes payment/receipt, UTC issue instant, labels, amount, allocations and live return/correction status. A reversal preserves all history and restores debt without moving money. Partial/full physical refunds select amounts from original allocations and restore those balances. Correction preserves/reverses original and atomically creates a linked replacement for the same flat. Refunded payments hide reversal/correction actions but allow remaining refunds. Legacy receipts explicitly identify missing original name snapshots.

Collection report supports society session context, from/to dates, authorized collector selection and method, with pagination and exact collection/refund/bookkeeping reversal/net totals. Filter CASH for cash collection events. Refund method is the actual return method; collector filter refers to original collection. Backdated corrections may change historical report ranges. This is a recorded ledger, not a bank/cash reconciliation attestation.

Mutation UUID keys remain in memory for unchanged retries after an uncertain result. Review history before editing/reloading after a connection failure. No requests, keys, bills, payments or receipts enter browser storage. Static shell navigation is allowlisted, with no worker data groups or API response caching. Private screens require the live backend and show safe connection/authorization messages offline. Angular interpolation escapes notes/reference/reasons. Production checks include browser private-cache/offline tests and print/media accessibility tests.

Run `npm run check` and `npm run test:e2e`. Backend-owned managed local stop/start refreshes builds and migration 013 while retaining accounts/data. Manual browser actions still include the OS print/PDF dialog and physical collection/refund reconciliation; no gateway was added.
